# 뉴스수집기 기능 개발 워크플로

새 기능을 개발할 때 브랜치 생성부터 메인 병합까지 순서대로 진행한다.
브랜치 이름: $ARGUMENTS

이 저장소의 메인 브랜치는 `main`이 아니라 `master`일 수 있다. 아래에서 "메인"은 `git symbolic-ref refs/remotes/origin/HEAD`로 확인한 기본 브랜치를 뜻한다 (확인이 안 되면 `main`, 없으면 `master`).

## 1. 현재 상태 확인

1. `git status --short --branch`로 현재 브랜치와 변경 사항을 보여준다.
2. 현재 브랜치가 메인이 아니면 "⚠️ 지금은 메인이 아닌 `<브랜치>` 브랜치에 있습니다."라고 경고하고, 메인으로 이동할지 AskUserQuestion으로 물어본다.
   - 이동하기로 하면 `git switch <메인>`으로 이동한다.
   - 이동하지 않기로 하면 여기서 멈춘다.
3. 커밋하지 않은 변경 사항이 있으면 브랜치를 옮기기 전에 알려주고, 어떻게 할지(먼저 커밋 / stash / 중단) 물어본다. 사용자 확인 없이 변경 사항을 버리지 않는다.

## 2. 새 브랜치 만들기

- `$ARGUMENTS`가 있으면 그 이름으로 `git switch -c $ARGUMENTS`를 실행한다.
- `$ARGUMENTS`가 비어 있으면 "어떤 기능을 개발할 건가요?"라고 묻는다. 답을 받으면 영어 소문자와 하이픈 형식의 브랜치 이름을 2~3개 제안하고(예: `feature/category-filter`, `add-category-filter`) AskUserQuestion으로 고르게 한다.
- 같은 이름의 브랜치가 이미 있으면 알려주고 다른 이름을 제안한다.

## 3. 개발 시작 안내

브랜치를 만든 뒤 다음을 안내한다.

1. "✅ `<브랜치>` 브랜치가 만들어졌습니다. 이제 개발을 시작하세요!"
2. `CLAUDE.md`, `AGENTS.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 짧게 정리해 보여준다. 최소한 다음을 포함한다.
   - 기술 스택: Next.js 버전과 주의점, 인증, DB/ORM, AI 호출 방식, Notion 연동, 스타일링
   - 컨벤션: 구현 전 `PRD.md`, UI 작업 전 `ui.md` 확인, 색상은 토큰 사용, Next.js API는 `node_modules/next/dist/docs/` 먼저 확인, 캐싱은 Cache Components 방식 등
   - 검사 명령: `npm run lint`, `npm run build`
3. "개발이 끝나면 '완료' 또는 'done'이라고 입력하세요."라고 알려준다.

이후 사용자가 요청하는 개발 작업은 평소처럼 돕는다.

## 4. 완료 처리 (사용자가 '완료' 또는 'done'을 입력했을 때)

1. 지금 작업 브랜치에 있는지 확인한다.
2. `git status --short`와 `git diff --stat`으로 변경된 파일 목록을 보여준다. 변경 사항이 없으면 알려주고 멈춘다.
3. `npm run lint`와 `npm run build`를 실행해 결과를 보여준다. 실패하면 오류를 보여주고 고칠지 물어본다. 실패한 채로 병합하지 않는다.
4. 변경 내용을 보고 커밋 메시지를 제안한다. 형식은 기존 커밋(`git log --oneline -5`)을 따른다: `한국어 요약: 무엇을 바꿨는지 한 줄 설명`.
5. AskUserQuestion으로 확인을 받는다 (제안대로 커밋 / 메시지 수정 / 취소).
6. 확인을 받으면:
   - 변경 파일을 커밋한다. `.env*` 같은 비밀 파일은 커밋하지 않는다.
   - `git switch <메인>` 후 `git merge --no-ff <브랜치>`로 병합한다.
   - 충돌이 나면 충돌 파일을 보여주고 멈춘 뒤 어떻게 할지 물어본다.
   - push는 사용자가 따로 요청할 때만 한다.

## 5. 작업 요약

병합이 끝나면 다음을 정리해 보여준다.

- 브랜치 이름과 병합 대상 브랜치
- 커밋 메시지와 커밋 해시
- 변경 파일 목록 (추가/수정/삭제)
- 구현한 기능 요약 (2~4줄)
- 다음에 할 일 제안 (예: `git push`, 작업 브랜치 삭제 `git branch -d <브랜치>`)
